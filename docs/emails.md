# Emails

The backend sends eight emails, all through Resend. Each has an HTML part (branded, light and dark) and a plain-text part.

| # | Subject | Trigger | Recipient | Link expiry | Code |
|---|---|---|---|---|---|
| 1 | Verify your Atmyshelf email | Signup, resend, or an email change | The address being verified | 24 hours, single use | `auth/accountSecurity.ts` `sendLink("verify")` |
| 2 | Reset your Atmyshelf password | Forgot password on an account with a password | The account email | 30 minutes, single use | `auth/accountSecurity.ts` `sendLink("reset")` |
| 3 | Sign in to Atmyshelf | Forgot password on a Google-only account | The account email | none (links to `/login`) | `auth/accountSecurity.ts` `forgotPassword` |
| 4 | Your Atmyshelf password changed | A completed password reset | The account email | none | `auth/accountSecurity.ts` `resetPassword` |
| 5 | Your Atmyshelf password changed | A password change in Settings | The account email | none | `auth/accountSecurity.ts` `changePassword` |
| 6 | Your Atmyshelf account was deleted | Account deletion | The account email | none | `auth/accountSecurity.ts` `deleteAccount` |
| 7 | You’re on the Atmyshelf launch list | A new waitlist signup (a repeat signup sends nothing) | The address that signed up | none | `waitlist/confirmation.ts`, `waitlist/plugin.ts` |
| 8 | ISBNdb rejected the API key | ISBNdb answers 401/403 | `ALERT_EMAIL` | none | `books/plugin.ts`, wired in `app.ts` |

## How they are built

`sendAccountEmail(to, subject, text, html?)` in `backend/src/modules/auth/email.ts` posts to Resend's HTTP API. `renderEmail(content, siteUrl)` in `backend/src/modules/auth/emailLayout.ts` turns `{ heading, paragraphs, button?, footnote? }` into `{ text, html }`; every input is a plain string and is HTML-escaped, so there is no raw-HTML input. `text` is sent as the fallback part and carries the link on its own line.

The HTML is a table layout with inline styles, so mail clients that ignore `<style>` still show the light design. Dark mode is a `prefers-color-scheme: dark` block in `<head>` using class names, with `!important` over the inline defaults. The look is black and white on the app's paper background: black (light) or paper-white (dark) for the card border, top bar, button and links, with no accent colour. The background, surface and text tones come from the light and dark themes in `frontend/src/themes.css`. The header mark has a light and a dark `<img>`, one shown at a time. Both load from `<FRONTEND_URL>/email/mark.png` and `mark-dark.png`, so the images only show once the frontend that ships `frontend/public/email/` is deployed.

## Config

- `RESEND_API_KEY` and `AUTH_EMAIL_FROM` (a sender on a verified Resend domain).
- `FRONTEND_URL` must be HTTPS. It builds the links and the image URLs.
- `ALERT_EMAIL` for email 8. Without it the alert is not sent.

Without the first three, `emailEnabled` is false: recovery and verification return 503, and the notification emails and waitlist confirmations are skipped.

## When sending fails

- Failures are logged without the address or link.
- Password-changed and account-deleted emails (4, 5, 6) are best effort. The change is not rolled back if the email fails.
- Verify and forgot-password emails (1, 2, 3) are not queued. The request that triggered them fails or is retried by the user after the one-minute cooldown.
- Waitlist confirmations (7) and the ISBNdb alert (8) are logged on failure. The signup is still kept.

## Adding an email

1. Call `renderEmail({ heading, paragraphs, button?, footnote? }, frontendUrl)` and pass `mail.text` and `mail.html` to the sender. Inside `createAccountSecurity`, use `notify(to, subject, content)`.
2. Keep the link in `button.url`; do not put URLs in paragraphs. Put "ignore this" and expiry sentences in `footnote`.
3. Add the row above and a test that asserts the subject and the link.

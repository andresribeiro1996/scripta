# Top Shelf Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "Top Shelf", a global hall of fame reached from a trophy in the Games header: a podium, book records, genre champions and hottest games for This month / All time and any genre, plus a shared top-10 leaderboard screen.

**Architecture:** Each game module (tier lists, arena, quizzes) exposes raw per-game facts through its public API. Top Shelf lives in the **community** module, because its plugin already holds the game modules' published-content deps, `resolveProfiles`, the engagement repository and the Discover item builder. A pure ranking function turns facts into boards; a service adds book cards and Discover items for what it returns and serves `GET /top-shelf`. Mobile renders two screens over a scroll-hiding bottom bar extracted from `SearchDock`.

**Tech Stack:** Fastify + node:sqlite (backend), `@scripta/shared` (types, client, tier math), Expo Router / React Native (mobile), node:test everywhere.

**Spec:** `docs/superpowers/specs/2026-10-21-top-shelf-design.md` — read it first; this plan argues from it.

## Global Constraints

- User-facing name is **Top Shelf**; code uses `topShelf` / `TopShelf` / route `/top-shelf`.
- Mobile only; no `frontend/` changes.
- Vote bar: a game feeds book records, podium and genre champions only with ≥ `TOP_SHELF_MIN_VOTERS = 5` distinct voters, owner excluded, anonymous included. Defined once, in `backend/src/modules/community/topShelf.ts`.
- Highest tier needs ≥ `HIGHEST_TIER_MIN_LISTS = 3` qualifying tier lists.
- Points: tournament title = 3; each appearance in a tournament, tier list or quiz = 1. Ties: titles desc, latest appearance desc, work id asc.
- "This month" = calendar month in `Europe/Lisbon`, computed on the server.
- Visibility = the Discover rule: owner resolves via `resolveProfiles`, or the tier list is promoted. Live tables at read time; a deleted/unpublished game vanishes from every period.
- A work counts at most once per game, after canonicalizing with `canonicalWorks` (a raw id missing from its map is kept as is).
- Hottest games: likes + votes + comments in the period, every visible published game, no vote bar, not genre-filtered, owner's own votes excluded.
- Words match the book page: "titles" (not "wins"), tier bands via `tierBand` ("Top tier"), not letters.
- No code comments (repo rule). New backend test files are appended to the explicit list in `backend/package.json` `test`. Shared changes need `npm run build --workspace @scripta/shared` before backend/mobile typecheck.
- `//` notes inside this plan's code blocks are plan notes — never copy them into code.
- Date tests set `process.env.TZ = "America/Sao_Paulo"` after imports (CI is UTC, this Mac is Lisbon; both hide local-time bugs).

## Review Focus

1. Start of a month (nothing qualifies yet) — every section shows its empty copy, never a broken podium; a podium of 1–2 books renders only those. → Task 10 model test `emptySections`.
2. Two editions of one work in a game, or a game stored under a since-merged work id — counted once, under the canonical id. → Task 6 test `counts a work once per game after canonicalizing`.
3. Publish event older than 30 days (moved to `events_history`) — still found, so the game isn't bucketed by draft `created_at`. → Task 5 test `finds publish times in events_history`.
4. Tournament slot with NULL `work_id`, or a completed tournament whose final has no winner — ignored, no crash. → Task 2 test `skips null slots and undecided finals`.
5. A genre chosen under All time with no entries this month — selection kept, menu still lists it, boards show empty copy. → Task 10 model test `keeps the selected genre in the menu`.

**Files:**
- Create: `backend/src/modules/community/topShelf.ts`
- Test: `backend/src/modules/community/topShelf.test.ts`

**Interfaces:**

- Produces:
  ```ts
  export const TOP_SHELF_MIN_VOTERS = 5;
  export const HIGHEST_TIER_MIN_LISTS = 3;
  export function topShelfMonthStart(now: Date): string; // ISO UTC instant of 00:00 on the 1st, Europe/Lisbon
  export type ShelfInput = {
    tierlists: TierlistShelfFacts[]; tournaments: TournamentShelfFacts[]; quizzes: QuizShelfFacts[];
    engagement: Map<string, { publishedAt: string; likes: number; comments: number }>;
    visibleOwners: Set<string>;                 // owner ids resolveProfiles returned
    canonical: Map<string, string>;             // raw work id -> canonical (missing = keep raw)
    genres: Map<string, { genres: string[] }>;  // canonical work id -> genres
  };
  export type Ranked = { workId: string; value: number };
  export function rankTopShelf(input: ShelfInput, opts: { since: string | null; genre: string | null }): {
    boards: Partial<Record<TopShelfBoard, Ranked[]>>;           // full order; risingStar only when since !== null
    genres: string[];                                           // genres with a champions entry this period, champion points desc — computed before the genre filter
    genreChampions: Array<{ genre: string; entry: Ranked }>;    // empty when opts.genre is set
    games: Array<{ ref: GameRef; ownerUserId: string; promoted: boolean; createdAt: string; likes: number; votes: number; comments: number }>; // score desc, zero dropped
  };
  ```
  Rules: a game is visible if `visibleOwners.has(ownerUserId)` or it is a promoted tier list. Publish time = `engagement.get(key)?.publishedAt ?? createdAt`; in period = `>= since`. Book boards use visible games with `voters >= TOP_SHELF_MIN_VOTERS`: tiered / quizzed = in-period games of that kind containing the work; crowned = champions with `settledAt` in period; champions = 3×titles + appearances of all three kinds; highestTier = mean over lists of each list's mean `tierPosition` of in-period placements (`castAt >= since`), only works with ≥3 such lists, ascending (lower = better, as `tierBand`); risingStar = works whose earliest publish time across **all visible games, vote bar or not**, is in period, valued by in-period qualifying appearances. `genre` filters every book board to works whose genres include it; `genres` is computed over all genres regardless of `opts.genre`. Every book board drops zero values. Ties per Global Constraints; highestTier ties: more lists, then work id.

# Works above editions: implementation plan

> **For agentic workers:** implement task by task, verify each, and commit
> each task separately. Steps use checkbox (`- [ ]`) syntax. After each task,
> run a spec review and then a quality review (`.claude/agents/`). Run the
> branch review once before the PR.

**Goal:** every catalog edition belongs to a work, works follow Open
Library's grouping (translations included), and every edition records its
language when a source states it. No user-visible change.

**Spec:** `docs/superpowers/specs/2026-10-01-works-design.md`. Also read
`docs/work-model-notes.md`.

**Base:** latest `main` (includes #103). The book-merge-seed session runs the
publisher importer and then the 50k seed **in production from the deployed
build**, writing `covers.sqlite` from another process while the API runs.
Deploys stay paused until that ends.
- Don't re-enable deploys.
- Rebase on `main` before starting and again before the PR.

**Where work keys come from today.** Writers of `ol_work_key`:
- `createBook({ …, workKey })` (`adapters/sqlite/sqliteBooksRepository.ts:93`)
  and the fill-only `setWorkKey(id, key)` (`:58`, `:188-191`; a single
  UPDATE, no transaction). `normalizeWorkKey` is at `domain/normalize.ts:13-16`.

Callers:
- `seed/seedCatalog.ts:19,28`: the only one passing `workKey` into
  `createBook`.
- `seed/importPublisherCovers.ts:239,242`, and `booksService.ts:172-178`
  (`saveHits`) and `:189,194` (`lookupDetails`): these create the edition
  without a key and call `setWorkKey` right after.

**Rules:**
- root `AGENTS.md` and `backend/AGENTS.md`;
- no code comments;
- new `*.test.ts` files go into `backend/package.json`'s `test` list;
- keep `setWorkKey` fill-only;
- don't change `createBook`'s `createdBy` / `books.created_by` semantics,
  because the details backfill orders by them;
- titles and `ta:` keys never choose a work.

## Task 1: Schema

**Files:** `adapters/sqlite/{books.sql,connection.ts}`, `domain/types.ts`,
and the repository tests.

- [ ] **`works` in `books.sql`:**
  `works (id TEXT PRIMARY KEY, ol_work_key TEXT UNIQUE, title TEXT NOT NULL,
  author TEXT NOT NULL, merged_into TEXT REFERENCES works(id), created_at TEXT NOT NULL)`.
- [ ] **Three new `books` columns:** `work_id TEXT REFERENCES works(id)`,
  `language TEXT` and `work_checked_at TEXT`.
  - Add them to `books.sql`'s `CREATE TABLE`, for new databases.
  - Add them as `PRAGMA table_info` + `ALTER TABLE` in `connection.ts`, for
    existing ones.
- [ ] **Indexes go in `connection.ts`, after the ALTERs.** `books.sql` runs
  first (`connection.ts:28`), so an index on a new column there fails with
  `no such column: work_id` on every existing database.
  - `CREATE INDEX IF NOT EXISTS idx_books_work ON books(work_id)`.
  - The Task 5 lookup index, only if Task 5 is built:
    `CREATE INDEX IF NOT EXISTS idx_books_work_lookup ON books(work_checked_at, created_by IS NOT NULL) WHERE isbn IS NOT NULL AND ol_work_key IS NULL AND details_status IS NOT NULL`.
- [ ] **`BookRow` gains the three fields.**
- [ ] **Tests.**
  - An existing database (the old-schema tests at
    `sqliteBooksRepository.test.ts:230, 285, 322`) gains the columns and
    indexes on boot, and a second open changes nothing.
  - `seedCatalog.test.ts:28` resets with `DELETE FROM works` after
    `book_keys` and `books`.
- [ ] **Mutation check:** move the `work_id` index into `books.sql`. The
  old-schema test must fail.

## Task 2: Every edition gets a work

**Files:** `sqliteBooksRepository.ts`, `booksService.ts` (`saveHits`),
`seed/importPublisherCovers.ts`, and the repository tests.

- [ ] **One `BEGIN IMMEDIATE` transaction each.** `createBook` and
  `setWorkKey` each run as one, as the library, arena, tier list, quiz and
  mural modules already do.
  - Today the books module uses a deferred `BEGIN` (`:83`, `:149`), and
    `setWorkKey` has none.
  - A deferred transaction that reads then writes fails at once with
    "database is locked" when the importer or seed process commits in
    between. The review reproduced it in 3 ms.
  - `createBook`'s existing-key check (`:80`) moves inside the transaction.
  - Insert the work before the book: node:sqlite enforces foreign keys.
- [ ] **`createBook`.** With a `workKey`, join the work holding it, or create
  it with this edition's title and author. Without a key, create a work of
  the edition's own.
- [ ] **`setWorkKey(id, key)`**, fill-only on the edition as today:
  - If no work holds `key` and the edition's work has only this edition,
    set the key on that work (`WHERE ol_work_key IS NULL`).
  - If another work holds `key`, move the edition there and set its old
    work's `merged_into` when that work has no editions left.
  - If the edition's `work_id` is NULL (the backfill hasn't reached it), join
    or create the keyed work directly.
- [ ] **Pass `workKey` into `createBook`** at `saveHits`
  (`booksService.ts:172-178`) and in the importer (`:239,242`).
  `NewBook.workKey` already exists. This stops each new hit leaving a
  throwaway work behind.
- [ ] **Empty identities.**
  - `fillIdentity` also fills the edition's work, in the same transaction:
    `UPDATE works SET title = ?, author = ? WHERE id = (SELECT work_id FROM books WHERE id = ?) AND title = ''`.
  - A titled edition joining a keyed work whose title is `''` fills it the
    same way.
- [ ] **Tests.**
  - Two editions with one key share a work.
  - A keyless edition gets its own.
  - A late key lands on the edition's own work when no work holds it.
  - A late key whose work already holds other editions: the edition joins
    them, and its old work gets `merged_into`.
  - `setWorkKey` on an edition that already has a key changes nothing.
  - An importer-style `''` edition, then `fillIdentity`, leaves its work
    titled.
  - A second connection committing between another transaction's read and
    write no longer fails `createBook`.
- [ ] **Mutation checks**, each must fail a test:
  - drop `AND ol_work_key IS NULL`;
  - drop the `merged_into` update;
  - deferred `BEGIN`.

## Task 3: Backfill existing editions

**Files:** `sqliteBooksRepository.ts`, `domain/ports.ts`, `plugin.ts`,
`backfill.ts`, and the tests.

- [ ] **Repository: `assignMissingWorks(limit)`.** One `BEGIN IMMEDIATE`
  transaction.
  - `.all()` reads `SELECT id, ol_work_key, title, author FROM books WHERE work_id IS NULL LIMIT ?`.
    Never `.iterate()` rows that are being updated.
  - It assigns each row a work by Task 2's rule and returns how many it did.
- [ ] **`plugin.ts`: start the loop without awaiting it, through
  `startDetailsBackfill`** (`backfill.ts:18-42`). That helper already gives a
  running guard, an unref'd timer and abort on close.
  - It runs at boot and retries every 10 minutes.
  - It loops `assignMissingWorks(250)` with `await new Promise(setImmediate)`
    after every batch, until a batch returns fewer than 250.
  - It logs the total at `info` when it is above 0.
  - Errors go to `app.log.error`, and the next tick retries.
  - After the seed this is about 65,000 rows. Synthetic: 3.1 s in total,
    with 14–22 ms batches.
- [ ] **Tests.**
  - A mixed catalog ends fully assigned, with keyed editions grouped.
  - The loop yields between batches. Copy the `setImmediate` probe from
    `community/archive.test.ts:180`.
  - A failed batch is logged and retried.
- [ ] **Mutation check:** remove the yield. The probe test must fail.
- [ ] **Measure** batch times on a 65k-row catalog, and put them in the
  commit message.

## Task 4: Edition languages

**Files:** `domain/normalize.ts`, `domain/ports.ts`,
`sqliteBooksRepository.ts`, `seed/rankedWorks.ts`, `seed/fetchRankedWorks.ts`,
`seed/seedCatalog.ts`, `seed/importPublisherCovers.ts`, the Open Library
adapter, and the tests.

- [ ] **Prefix lists.** In `normalize.ts`, export the Portugal and Brazil
  prefix lists separately: `978972`/`978989` and ISBN-10 `972`/`989` for
  Portugal; `97885`/`97865` and `85`/`65` for Brazil. Build
  `PORTUGUESE_ISBN13_PREFIXES` from them, and have `rankedWorks.ts` import
  the Portugal list instead of keeping its own `PORTUGAL_ISBN_PREFIXES`.
- [ ] **`editionLanguage(marcCodes, isbn)`** goes in `normalize.ts`.
  - MARC to two-letter: `eng`→`en`, `por`→`pt`, `spa`→`es`, `fre`→`fr`,
    `ger`→`de`, `ita`→`it`, `dut`→`nl`, `cat`→`ca`, `glg`→`gl`,
    `jpn`→`ja`, `chi`→`zh`, `rus`→`ru`.
  - The first mappable code wins; none mappable gives `null`.
  - For `pt`, the ISBN group sets the region: `pt-PT`, `pt-BR`, else `pt`.
- [ ] **Repository.**
  - `setLanguage(id, tag)` is fill-only.
  - `replaceLanguage(id, tag)` is for Open Library's own edition record
    (Task 5).
  - Add `setLanguage` to the `SeedRepo` Pick (`seedCatalog.ts:12`) and to
    `ImportDeps.repo` (`importPublisherCovers.ts:46`).
- [ ] **Seed.**
  - `SeedEntry` gains `languages: strings(edition?.language)`. The fetch
    already requests `editions.language` (`rankedWorks.ts:18`).
  - `seedBook` sets
    `editionLanguage(entry.languages.length > 0 ? entry.languages : [entry.lang], entry.isbn)`
    in both branches: new and existing rows (`seedCatalog.ts:17-25`).
- [ ] **Importer.** `lookupOpenLibrary`
  (`backend/scripts/import-publisher-covers.mjs:39-47`) parses `languages`.
  - Use the Open Library adapter's parser, shared with Task 5.
  - Set the language from it, falling back to `pt` only for Portugal ISBNs;
    others stay NULL.
  - Note that the lookup only runs for products with no author in the feed
    (`importPublisherCovers.ts:220-233`).
- [ ] **Tests.**
  - The mapping table, and the three Portuguese regions (ISBN-13 and
    ISBN-10).
  - Unknown codes.
  - `setLanguage` stays fill-only; `replaceLanguage` replaces.
  - The seed uses edition languages before the list's.
  - The importer's fallback applies only to Portugal ISBNs.
- [ ] **Mutation checks**, each must fail a test:
  - swap the PT and BR lists (the region test);
  - make `setLanguage` overwrite (the fill-only test).

## Task 5: Background work-key lookup (gated)

**Gate.** Build this only after Tasks 1–4 are live and the after-deploy check
shows enough keyless editions to be worth it: `keyless_checked` in the
thousands.
- The details backfill already stores Open Library's work key for every
  catalog book it checks (`booksService.ts:184-196`), about 7,200 a day.
- Most keyless editions it leaves are books Open Library didn't match, so
  most `/isbn/` calls would 404.

**Files:** `booksService.ts` (a method beside `backfillDetails`), the Open
Library adapter, `plugin.ts`, and the tests.

- [ ] **A service method**, with the edition lookup injected as an adapter.
  Tests stub `fetch` the way `openLibraryCatalog.test.ts:7-22` does.
- [ ] **Run it through `startDetailsBackfill`** with a 2 s interval, in the
  normal Open Library lane (no `urgent`), as `backgroundCatalog` does
  (`plugin.ts:74-78`). One lookup in flight at most.
- [ ] **Pick the next edition with this exact SQL**, using the Task 1 index.
  Users' rows come first, as `listUncheckedDetailIds` orders them:
  ```
  SELECT id, isbn, work_checked_at FROM books WHERE isbn IS NOT NULL AND ol_work_key IS NULL AND details_status IS NOT NULL ORDER BY work_checked_at, created_by IS NOT NULL LIMIT 1;
  ```
  Skip the tick when that row's `work_checked_at` is under 30 days old.
- [ ] **Outcomes.**
  - A hit: `setWorkKey(works[0].key)` and `replaceLanguage`, then stamp
    `work_checked_at`.
  - A 404, or a record without `works`: stamp.
  - `SourceUnavailableError` (429, 5xx, timeout): stamp so one bad ISBN can't
    stall the loop, `warn`, and pause until the error's `retryAt` or
    10 minutes, whichever is later. `runBatch` can return a `retryAt`.
  - Any other error: `app.log.error`, unstamped.

  A failure is never recorded as "nothing there".
- [ ] **Tests.**
  - A hit stores the key and language and moves the edition.
  - A 404 stamps.
  - A 429 with Retry-After pauses the loop and stamps at most one edition.
  - Recently checked editions are skipped.
  - Pin the pick's plan with `EXPLAIN QUERY PLAN`: an index scan, no temp
    B-tree.
- [ ] **Mutation checks**, each must fail a test:
  - stamp without pausing;
  - drop the 30-day check.

What to expect:
- `unassigned` reaches 0 once the backfill finishes.
- `mismatched` is 0.
- `keyless` levels off at the books Open Library doesn't know; it does not
  reach 0.
- `keyless_checked` decides Task 5's gate.
- `language` stays NULL for existing seed rows until the seed is re-run (the
  command at `backend/README.md:163`), which also creates any newly ranked
  books.

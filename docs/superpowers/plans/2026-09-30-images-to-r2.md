# Images to R2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every stored image (book covers, gallery uploads, avatars) lives in the public R2 bucket `atmyshelf-images`, served from `https://images.atmyshelf.com`. The Railway volume then holds only SQLite databases, and every user file has a durable home.

**Architecture:**
- **One object store.** A single object-store abstraction in `backend/src/storage/`, with two implementations:
  - **R2**, over the S3 API, signed with `aws4fetch`. Production uses it whenever `R2_IMAGES_BUCKET` is set, which boot requires on Railway.
  - **Filesystem**, for local dev and tests, served by a `GET /files/*` route.
- **Modules stay isolated.** Each module keeps its own port and gets its own store instance from `plugin.ts`.
- **Object keys** are flat and account-free:
  - `covers/<id>.webp` and `covers/<id>-thumb.webp`
  - `gallery/<id>.webp`
  - `avatars/<id>.webp`
- **Old URLs keep working.** A one-time copy uploads today's files under the same ids. The three old file routes become permanent `301` redirects to the new URLs, so every absolute URL already stored in library documents, community events, tier-list snapshots, quizzes, arena slots and mural covers keeps working with no data rewrite.

**Tech Stack:** Fastify, TypeScript, `node:test`, `aws4fetch` (new dependency, ~6 KB, no transitive deps).

**Spec:** phase 2 of `docs/superpowers/plans/2026-09-30-launch-catalog-storage-backups.md` (written by the backups session), plus the decisions below, agreed in chat on 2026-09-30.

## Decisions

- **Scope:** covers, gallery uploads and avatars all move. The volume keeps only `*.sqlite`.
- **Bucket and variables:** already created and set by the user and the backups session. Bucket `atmyshelf-images` (WEUR, public via custom domain `images.atmyshelf.com`, r2.dev off). Railway `scripta` service variables: `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_IMAGES_BUCKET=atmyshelf-images`, `R2_IMAGES_PUBLIC_URL=https://images.atmyshelf.com`. One token has Object Read & Write on both buckets.
- **Copy, don't re-resolve, and redirect old routes.** This deviates from the phase-2 text ("no redirect route and no copy"). The user allowed old links to break but didn't require it. Absolute image URLs are persisted in at least six places, so letting them die breaks images across existing content. Copying all of `/data`'s files (~30 MB) under the same ids, plus three one-line redirects, avoids that and avoids rewriting data across modules.
- **Uploads** carry `Cache-Control: public, max-age=31536000, immutable` and `Content-Type: image/webp`. Every stored image is already WebP.
- **Local dev never touches R2.** No `R2_IMAGES_BUCKET` means the filesystem store under `FILES_STORAGE_PATH` (default `./data/files`), served by `GET /files/*`.
- **Account deletion removes files before rows.** A failed R2 delete aborts the deletion with the account intact, so it can be retried. It never leaves an account half-deleted with files orphaned.

## Global Constraints

- Minimum code, no code comments, one new dependency (`aws4fetch`) and no others (root `AGENTS.md`).
- Catch only the specific error you expect. An R2 failure (non-2xx, network error) propagates as an error. It is never reported as "nothing there", except a `404` on `get`, which means missing.
- Modules never import each other's internals. `backend/src/storage/` is shared infrastructure, like `backend/src/config/`.
- Every new `*.test.ts` file is appended to `backend/package.json` `"test"`. Backend tests run with `DOTENV_CONFIG_PATH=/nonexistent/.env`.
- Object keys are exactly: `covers/<id>.webp`, `covers/<id>-thumb.webp`, `gallery/<id>.webp`, `avatars/<id>.webp`.
- Public URL of a key: `${R2_IMAGES_PUBLIC_URL}/${key}` on R2, and `${PUBLIC_API_URL}/files/${key}` on the filesystem store.
- On Railway (`RAILWAY_VOLUME_MOUNT_PATH` set), boot fails unless all five `R2_*` image variables are set. Production can't silently fall back to disk.
- Don't touch `backend/scripts/start-with-litestream.sh` or `backend/litestream.yml` (another session's area).
- Use installed dependencies. If you add `aws4fetch`, do it with `npm install aws4fetch --workspace backend`, and commit `package.json` and `package-lock.json` together.

## Review Focus

1. **R2 returns 403 or 5xx on upload.** An upload or cover lookup fails loudly. The DB never points at an image that isn't stored: save the blob first, then the row. Pinned in Task 1 (the adapter throws on non-2xx) and Task 3 (a gallery upload whose save rejects creates no row).
2. **Account deletion when R2 is down.** Deletion fails and the account and its rows stay. Pinned in Task 5.
3. **A stored old URL** (`https://api.atmyshelf.com/covers/cached/<id>/thumb`, `/gallery/<id>/file`, `/auth/avatar/<id>/file`) answers `301` to the right new URL. Pinned in Tasks 2, 3 and 4.
4. **An id in a redirect route that isn't a UUID** gets `400`, never a redirect built from attacker input. Pinned in Tasks 2, 3 and 4.
5. **Keys with path traversal** (`../`) into the filesystem store or the `/files/*` route are rejected. Pinned in Task 1.

**Interfaces:**
- Produces, in `objectStore.ts`:

```ts
export interface ObjectStore {
  put(key: string, bytes: Buffer, contentType: string): Promise<void>;
  get(key: string): Promise<Buffer | null>;
  delete(key: string): Promise<void>;
  urlFor(key: string): string;
}
export function assertObjectKey(key: string): void;
export function createFsObjectStore(root: string, publicBaseUrl: string): ObjectStore & { root: string };
```

- `r2ObjectStore.ts`: `createR2ObjectStore(options: { endpoint: string; accessKeyId: string; secretAccessKey: string; bucket: string; publicUrl: string }): ObjectStore`
- `createObjectStore.ts`: `createObjectStore(): ObjectStore`. It builds from `env` and returns one shared instance. Modules may call it; it is infrastructure, not a module.
- New env vars in `env.ts`, all optional strings:
  - `R2_ENDPOINT` (url)
  - `R2_ACCESS_KEY_ID`
  - `R2_SECRET_ACCESS_KEY`
  - `R2_IMAGES_BUCKET`
  - `R2_IMAGES_PUBLIC_URL` (url)
  - `FILES_STORAGE_PATH` (default `./data/files`)
- Add a `superRefine` rule: when `RAILWAY_VOLUME_MOUNT_PATH` is non-empty, all five `R2_*` image variables are required. Report it as one issue listing the missing names.

**Behaviour:**
- **`assertObjectKey(key)`** throws `Error("Invalid object key")` unless the key matches `/^(covers|gallery|avatars)\/[0-9a-f-]{36}(-thumb)?\.webp$/`. Every store method calls it first.
- **The filesystem store** writes to `join(root, key)`. It creates parent directories. `get` returns `null` only when the file doesn't exist (`ENOENT`) and rethrows anything else. `delete` ignores `ENOENT` only. `urlFor(key)` returns `${publicBaseUrl}/files/${key}`.
- **The R2 store** uses `new AwsClient({ accessKeyId, secretAccessKey, service: "s3", region: "auto" })` against `${endpoint}/${bucket}/${key}` (path-style):
  - `put` sends `PUT` with headers `Content-Type` and `Cache-Control: public, max-age=31536000, immutable`, and throws `Error(\`R2 PUT ${key} failed: HTTP ${status}\`)` on non-2xx.
  - `get` sends `GET`, returns `null` on `404`, throws on any other non-2xx, and returns `Buffer.from(await res.arrayBuffer())`.
  - `delete` sends `DELETE`, treats `204`, `200` and `404` as success, and throws otherwise.
  - `urlFor(key)` returns `${publicUrl}/${key}`.
- **`createObjectStore()`** returns the R2 store when `env.R2_IMAGES_BUCKET` is set, and otherwise the filesystem store at `env.FILES_STORAGE_PATH` with `env.PUBLIC_API_URL`.
- **`GET /files/*`** is registered in `app.ts` only when the store is the filesystem store. It validates the key with `assertObjectKey` (400 on failure), reads it with `get` (404 on `null`), and replies with `image/webp` and the same immutable `Cache-Control`.

### Task 6: One-time copy of existing files to R2

**Files:**
- Create: `backend/scripts/copy-files-to-r2.mjs`. It is plain ESM because production runs `dist/` and has no `tsx`. It imports `aws4fetch` directly.

**Behaviour:**
- It reads `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` and `R2_IMAGES_BUCKET` from the environment and fails loudly if any is missing.
- It walks three source directories, defaulting to production's paths and overridable by flags:
  - `--covers /data/covers-files`: `<id>.webp` → `covers/<id>.webp`, and `<id>-thumb.webp` → `covers/<id>-thumb.webp`.
  - `--gallery /data/gallery-files`: `<userId>/<id>.webp` → `gallery/<id>.webp`.
  - `--avatars /data/avatar-files`: `<userId>/<avatarId>.webp` → `avatars/<avatarId>.webp`.
- It skips any file whose name doesn't match the UUID pattern and logs it.
- It uploads with the same headers as the R2 store: `PUT`, `image/webp`, and the immutable `Cache-Control`. It's idempotent: re-uploading the same key is harmless.
- It prints per-kind counts: uploaded and skipped. It exits non-zero on any failed upload, but only after trying all files, and lists the failures.
- The flag defaults come from the current Railway values. Check them with `ls /data` in the handover step; don't guess. If gallery's actual directory differs, the user passes `--gallery`.
